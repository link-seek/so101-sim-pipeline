# 序章：为什么要在仿真中评测机器人

> SO101 仿真评测教程 · 序章

---

## 1. 真机评测的困境

如果你亲手操作过机器人，一定对这些场景不陌生：

- **硬件损耗**：SO-101 的伺服电机在连续遥操作 2 小时后发热严重，齿轮箱磨损导致关节精度下降
- **采集耗时**：录制 100 个 pick-and-place 演示需要一整天，还得人工筛选失败 episode
- **安全围栏**：机器人突然甩动可能打碎桌面物体、损坏自身，必须有人值守
- **不可复现**：同一个策略今天成功明天失败，光照、物体位置、电池电量都在变

这些问题的本质是：**真机评测的成本高、速度慢、不可控**。

仿真快了一个数量级——1024 个环境并行，50 个 episode 30 秒跑完。但代价是：

> **仿真里学到的策略，放到真机上可能完全不能用。**

这就是 **Sim-to-Real Gap**（仿真到现实的鸿沟）。在我们的项目中，它以一个具体的形式出现：训练数据来自真机照片，评测在 MuJoCo 仿真中渲染，模型学到的视觉特征跨域失效。

所以仿真评测不是"用仿真替代真机"，而是**在仿真中快速验证方案、暴露问题、建立 baseline**——最终目标仍然是真机可用。

---

## 2. 我们做了什么

我们用 SO-101（一个 6-DOF 开源机械臂）走完了完整流程：从仿真训练到仿真评测，再到 LIBERO benchmark 对接。

| 路线 | 方法 | 评测结果 | 训练耗时 |
|------|------|----------|----------|
| PPO（强化学习） | MuJoCo + Warp GPU 并行 | **98-100%** 成功率 | 86 分钟 |
| SmolVLA（行为克隆） | LeRobot + sim twin 数据集 | **47%** 成功率 | ~10 小时 |

PPO 快速验证了环境可学性，VLA 验证了视觉方案的可行性。两者互补，不是替代关系。

我们为整个流程提供了 **4 个 Docker 镜像**，预装所有依赖，`docker run` 一条命令即可运行：

| 镜像 | 用途 |
|------|------|
| `so101-ppo` | PPO 训练 + 评估 |
| `so101-mujoco` | SmolVLA 训练 + Grid Sweep 评测 |
| `so101-eval` | LIBERO 评测 |
| `so101-train` | SmolVLA 训练 + 回放验证 |

## 3. 本教程交付什么

本教程不只是"带你走一遍流程"，而是交付一套**可复用的评测基础设施**。具体包括四个层面：

### 3.1 实战教程

基于真实项目的完整踩坑记录，不是 demo 级别的 hello world。Ch1-Ch4 跑通训练和评测，Ch5 建立方法论，Ch6-Ch8 从开箱即用到自定义扩展。

### 3.2 Docker 镜像 + 脚本

预装所有依赖，`docker run` 一条命令即可训练和评测。各镜像细节见 Ch1。

### 3.3 评测流水线

GitHub Actions 一键触发（`franka-eval.yml` / `robot-switch.yml`，workflow_dispatch），华为云 ECS（V100）执行，自动归档结果到 OBS。被测模型只需提供：

| 必填项 | 说明 | 示例 |
|--------|------|------|
| 模型路径 | OBS 路径或本地 checkpoint | `obs://so101-sim-pipeline/models/so101-smolvla` |
| 机器人类型 | 字符串标识 | `so101` / `franka` / `sawyer` |
| 评测环境/任务 | 在哪个 benchmark 上评 | `libero_spatial` / `WarpPickLift-v1` |

| 可选项 | 默认值 | 说明 |
|--------|--------|------|
| 评测 episode 数 | 10 | LIBERO/SmolVLA 官方协议（Ch6/Ch7 实测取值） |
| 随机种子 | 7 | 可复现性（Ch6/Ch7 实测取值） |
| 额外配置 | 空 | 自定义参数（如 camera names、action scale） |

平台自动完成环境搭建、评测执行、结果归档（JSON 报告 + 视频 + 截图），输出标准化评测报告。

### 3.4 自定义扩展方案

支持任意模型、任意机器人的评测接入。Ch7 展示 L1 扩展（RoboSuite 内置机器人，文件补丁+挂载机制，Sawyer 实测跑通），Ch8 给出 L2 扩展方案（SO101 自定义集成，方案级、未实施）。

**四者组合的目标**：后续新人不需要把原理搞得很懂，就能评测已有机器人的模型；需要接入新机器人时，有标准路径可循。

## 思考题

1. **Sim-to-Sim 验证消除了视觉域差异，但物理域差异呢？**  
   提示：MuJoCo 的接触模型和真实接触有什么不同？

2. **评测平台的接口定义中，为什么"机器人类型"是必填项？**  
   提示：不同机器人的关节维度、动作空间、观测空间都不同。模型是在特定机器人上训练的，评测必须在匹配的环境中方有意义。Ch5 的 LIBERO 0% 就是反面教材。

3. **仿真评测结果能代表真机表现吗？什么情况下可以，什么情况下不行？**  
   提示：想想 Sim-to-Real Gap 的来源和我们选择 sim-to-sim 路线的原因。
